## 抽样逻辑

抽样算法为 `balanced-stratified-v1`，固定种子为 `p1d-cmooc-2024-2025-v1`。同一数据指纹、算法版本和种子会产生相同的项目集合与显示顺序。

正式角色、P99、P95 和普通基线采用预先设定的 35%/15%/25%/25% 配额，再在课程及平台角色细分层内进行确定性随机排序。这样既能研究正式促进者，也保留大量平台登记学习者和普通长度反例，避免把“长帖”当成身份或促进功能代理。

## 编码与自动校验

编码规则见 [cMOOC 促进功能人工编码代码本 v1](FACILITATION_FUNCTION_CODEBOOK_V1.md)。`research:review:validate` 会拒绝以下结果：

- 项目缺失、重复或多出；
- 表头出现变化；
- `yes/no/uncertain`、功能标签或裁决状态不在代码本枚举内；
- 次要功能不是合法 JSON 数组、存在重复或与主要功能重复；
- `no/uncertain` 仍被强行分配功能；
- 置信度越界、编码者号不合规或编码轮次非法。

校验输出只包含聚合数量，不输出事件映射、正文或身份字段。

## 当前边界与下一步

当前批次是一套“抽样和编码契约”，不是包含正文的编码包。P1e 已实现本地只读审阅器：按私有映射从原始 Excel 在内存中读取入样主帖，隐藏潜在身份线索后展示，不生成新的正文副本。实现与使用方法见 [P1e 本地促进功能盲审查看器实施报告](P1E_LOCAL_REVIEW_VIEWER_REPORT_20260718.md)。

在双人编码和裁决完成前，`event_function_score` 继续为空，任何人工或模型标签都不得进入学习者画像或在线干预策略。
