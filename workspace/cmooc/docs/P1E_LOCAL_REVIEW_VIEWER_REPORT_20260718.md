# P1e 本地促进功能盲审查看器实施报告

日期：2026-07-18（Asia/Shanghai）

## 结论

P1e 已把 P1d 的 300 条盲化抽样转化为可实际编码的本地工作流。查看器按私有映射从原始 Excel 定位入样主帖，在内存中净化 HTML 和潜在身份线索，只向编码者显示盲化项目号、标题与正文。磁盘草稿和最终 CSV 只保存功能标签，不保存论坛正文、作者、课程、平台角色、来源、长度或后续互动结果。

该工具与 Next.js、Prisma、学习者画像和自动发布链路完全分离，只监听 `127.0.0.1`。它解决的是“事件在当时是否承担促进功能”的人工编码问题，不推断发布者的永久身份或人格。

## 使用方法

先使用检查模式验证 DPAPI 密钥、P1c 研究库、P1d 批次和 8 个原始 Excel 的哈希：

```powershell
npm run research:review:serve -- `
  -InputRoot "C:\Users\tiany\Nutstore\2\我的坚果云\cmooc研究数据24-25" `
  -CoderId coder_a `
  -Round 1 `
  -CheckOnly
```

正式编码时去掉 `-CheckOnly`。启动器会打开默认浏览器；终端保持运行，完成后按 `Ctrl+C` 关闭服务。

```powershell
npm run research:review:serve -- `
  -InputRoot "C:\Users\tiany\Nutstore\2\我的坚果云\cmooc研究数据24-25" `
  -CoderId coder_a `
  -Round 1
```

第二名编码者应使用不同的 `CoderId` 和 `-Round 2` 独立完成同一批次。全部 300 条保存后，“导出编码表”才会启用。导出的 CSV 可用 P1d 校验器检查：

```powershell
npm run research:review:validate -- `
  --batch-dir "$env:LOCALAPPDATA\cmooc-research\p1d\facilitation-review-300-v1" `
  --annotations "C:\path\to\exported-annotations.csv"
```

## 数据与安全边界

- DPAPI 密文继续保存在 `%LOCALAPPDATA%\cmooc-research\secrets`，启动器不输出密钥；Python 读取后立即从自身环境变量中移除。
- 启动前验证 P1c 数据库 SHA-256、数据集指纹、投影关闭状态，以及 8 个 Excel 的路径与 SHA-256；任一变化均拒绝启动。
- 只扫描两个主帖文件；只在 HMAC 与 P1d 入样事件匹配后提取标题和正文，不构造全量正文副本。
- 姓名和网名词表只在内存中用于替换；同时隐藏邮箱、电话、身份证号、外部账号、凭据样式、URL 和 `@` 账号。
- 页面使用 `textContent` 渲染正文，禁止 HTML 执行；CSP、`no-store`、`nosniff`、禁止嵌入和最小权限响应头固定启用。
- 会话令牌放在 URL fragment 中，页面读取后立即从地址栏移除；API 还校验精确 Host、同源 Origin 和 `X-Review-Token`。
- 草稿采用本地原子写入，只含盲化项目号、标签、编码者号和轮次。仓库/同步目录、UNC 路径均不能作为草稿根目录。
- 未完成全部项目不能导出；浏览器界面不提供身份、角色、课程、来源或结果检索入口。

完整威胁边界与页面契约见 [P1e 查看器设计与安全规范](P1E_REVIEW_VIEWER_DESIGN.md)。

## 真实数据验证

在真实 2024—2025 匿名化论坛导出上执行 `-CheckOnly`，结果为：

| 项目 | 结果 |
|---|---:|
| 入样内容定位 | 300 / 300 |
| P1c 数据库哈希 | 通过 |
| 原始 Excel 哈希 | 8 / 8 通过 |
| 身份盲化契约 | 通过 |
| 至少发生一次自动替换的条目 | 169 |
| 自动替换总数 / P95 / 最大值 | 970 / 13 / 226 |
| 自动替换不少于 20 处的条目 | 7 |
| 疑似 Excel 单元格截断 | 1 |
| 正文持久化 | 0 |
| P1e 草稿文件 | 0 |
| 本次检查耗时 | 8.3 秒 |

检查模式不会生成编码结果。自动替换是风险降低措施，不是对自由文本匿名性的绝对保证；7 条重度替换项目会在界面提示语义可能受损，必要时应编码为 `uncertain` 并进入裁决。查看器只能由获准接触匿名化原始数据的编码者在受控本机使用。`event_function_score` 仍保持为空，只有真实双人编码与裁决完成后才能进入下一阶段。

## 浏览器与视觉核验

使用合成帖子运行同一服务端和前端，完成了桌面 1440×900 与移动端 390×844 检查，并实际执行“存在促进功能—主要功能—次要功能—置信度—保存并下一条”。进度从 0/12 正确更新为 1/12；地址栏不再保留令牌；控制台无错误；两个尺寸均无横向溢出。

与 [概念图](design/p1e-blind-review-concept.png) 的对照如下：

| 核验点 | 实现结果 |
|---|---|
| 深蓝顶栏、青绿色状态强调 | 一致 |
| 左侧盲化进度、中央阅读、右侧编码 | 桌面一致；移动端按进度—正文—编码顺序折叠 |
| 正文采用高可读衬线字体与宽行距 | 一致 |
| 不显示作者、课程、角色和来源 | 一致 |
| 保存后推进并显示完成状态 | 一致，并增加未保存离开提醒 |
| 概念图中的“前序主题语境” | 当前未实现；为避免引入未入样内容和身份线索，P1e 仅显示本条主帖 |

## 自动化验证

P1e 新增 7 个专项测试：3 个内容定位/脱敏测试和 4 个服务/API/持久化测试。全量研究测试共 17 个，均通过。测试覆盖错误 HMAC、源文件或数据库变化、Host/Origin/令牌伪造、超大请求、非法标签、未完成导出、草稿正文泄漏与盲化字段泄漏。

## 下一门槛

1. 由两名编码者阅读代码本后独立完成 300 条编码，不能共享中间判断。
2. 对 `yes/no/uncertain`、主要功能、次要功能和低置信度分歧进行盲态裁决。
3. 裁决完成后再由数据管理员连接私有事件映射；在此之前不揭示平台角色或历史学伴身份。
4. 通过课程与时间留出评估人工标签的稳定性，再决定是否训练功能识别模型；不得直接把未裁决标签接入在线干预。

## 2026-07-19 工作量修订

上述“300 条全部完成后才能导出”是 P1e 当时的保守门禁，现已由 [P1g 现实可行的人机校准方案](P1G_PRAGMATIC_HUMAN_LLM_CALIBRATION_REPORT_20260719.md)替代为默认流程。查看器现在允许随时导出已保存项目，文件状态固定为 `pilot_single_coded`/`pilot_double_coded`，不能进入原 P1f 全量裁决。正式验证使用与 pilot 隔离的固定子集；全量 300 条双人编码仅作为可选增强，不再是毕业论文实施的默认要求。
