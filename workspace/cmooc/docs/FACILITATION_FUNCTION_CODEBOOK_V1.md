# cMOOC 促进功能人工编码代码本 v1

## 编码目标与单位

编码单位是一条主帖事件，目标是判断该事件在当时是否表现出促进网络连接、知识建构或持续参与的功能。编码对象是“这一次行动”，不是作者的永久身份、人格、教师地位或智能学伴来源。

代码本与 CIE 学习交互层级相互独立：促进功能描述环境中的支持行动，CIE 描述学习者表现出的认知参与。不得因为帖子复杂、篇幅较长或后来回复较多，就把促进功能直接推断为高阶认知，也不得反向推断作者身份。

## 盲法与证据边界

- 编码表不显示课程、作者、平台角色、来源类型、字数、网络中心性或最终回复数。
- 编码者只能依据事件发生时已经存在的帖子内容和必要的前序主题语境。
- 不查看最终点赞、最终回复数、后续中心性或其他未来结果。
- 长帖 P95/P99 只是抽样入口，不是标签证据。
- 编码表不得复制帖子原文、网名、联系方式或可识别信息；如需备注，只使用抽象理由码。

## 第一步：是否存在促进功能

`facilitation_present` 只能填写：

- `yes`：至少一种促进功能有明确、可定位的行为证据；
- `no`：主要是个人陈述、作业提交、信息转发或其他内容，没有可识别的促进他人/网络行为；
- `uncertain`：缺少必要语境，或证据不足以在 `yes/no` 间判断。

只有填写 `yes` 时才能填写主要和次要促进功能。`no` 与 `uncertain` 不得强行分配功能标签。

## 第二步：促进功能标签

| 标签 | 纳入标准 | 常见排除情形 |
|---|---|---|
| `resource_seeding` | 引入与主题有关、可供他人继续学习或连接的资源、案例或工具 | 仅粘贴链接且没有主题关联线索 |
| `question_guiding` | 用开放问题、分步问题或澄清问题推动他人继续表达和探究 | 修辞性问句、测验式检查答案 |
| `idea_bridging` | 明确连接不同帖子、观点、参与者、概念或实践场景 | 只罗列多个观点而未说明关系 |
| `amplification` | 识别并突出他人贡献，使其获得进一步讨论机会 | 仅表示同意、点赞或礼貌致谢 |
| `synthesis` | 对分散讨论进行整合、比较、归纳，并形成可继续推进的结构 | 单纯摘要自己的原帖 |
| `cognitive_challenge` | 提供反例、矛盾、边界条件或替代解释，促使观点修正 | 人身否定、无理由反对、制造冲突 |
| `affective_support` | 对困惑、挫败、孤立等情绪提供具体共情、鼓励或任务拆解 | 泛化表扬、模板式“加油” |
| `coordination` | 组织活动、明确协作步骤、分配任务或帮助参与者进入讨论 | 单向发布行政通知且不支持参与 |
| `peer_exchange` | 以平等参与者身份分享可回应的经验并明确邀请互学 | 单纯个人作业或自我展示 |

`primary_function` 填写最能解释该事件主要作用的一个标签。`secondary_functions` 使用 JSON 数组，例如 `["idea_bridging","question_guiding"]`，不得重复主要标签。

## 置信度

`confidence` 使用 0—1 数值：

- `0.80–1.00`：行为证据直接且语境充分；
- `0.60–0.79`：基本明确，但存在一种合理替代解释；
- `0.40–0.59`：证据有限，应进入复核；
- 低于 `0.40`：应优先使用 `uncertain`，不提交肯定标签。

## 双人编码与裁决

P1g 之后默认采用“试编码—冻结代码本—留出验证”而非全量双标：

1. 第一名编码者先完成可承受数量的试编码，并导出明确标记为 `pilot` 的文件；试编码只用于发现歧义和估计工作量，不进入最终效度检验。
2. 冻结代码本后，从未参加试编码的项目中确定性抽取验证子集。两名编码者只需独立完成该子集，不交换判断。
3. `facilitation_present` 是首要信度指标；主要功能只在双方均为 `yes` 的条件子集中计算。次要功能和主观置信度属于次级/探索性指标，不作为首要通过门槛。
4. 同时报告观察一致率、Cohen's kappa、Gwet's AC1、`yes`/`no` 特异一致率及区间，避免类别不平衡时只看单一 kappa。
5. `yes/no/uncertain` 不一致、主要功能不一致，或任一编码者置信度低于 0.60 时进入争议复核。
6. 若确实无法取得第二名编码者，可由同一编码者在预先记录的间隔后复测同一验证子集；结果必须称为“编码者内重复性”，不得写成“双人编码者间信度”。
7. 裁决只解决事件功能，不讨论或揭示作者平台身份。只有验证设计、争议处理和效度检验完成后，才能将标签连接到私有事件映射。

## 禁止性规则

- 禁止把 `CREATOR` 自动改写为教师，也禁止把 `LEARNER` 自动改写为普通学生。
- 禁止依据长帖、网名、职务文字或写作风格猜测历史学伴身份。
- 禁止把促进者帖子作为学生心理状态、人格或认知层级的直接证据。
- 禁止用后续互动结果反向修正当时的促进功能标签。
- 禁止将未经裁决的人工标签或模型弱标签直接用于在线自动干预策略。
