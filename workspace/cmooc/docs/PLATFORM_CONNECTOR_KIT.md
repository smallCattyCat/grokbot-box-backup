# 在线学习社区接入包

- 版本：`connector-kit-v1`
- 日期：`2026-08-29`
- 交付形态：`一个客户一套隔离部署`
- 当前结论：通用课程清单、精确连接器选择、白标入口和零发布运行骨架已实现；目标社区连接器需在其测试环境中完成

## 1. 这套接入包解决什么

产品内核把“如何判断课程需要什么”与“如何从某个平台读取课程”分开：

```text
目标社区只读接口或页面
→ 平台连接器
→ 统一课程事件、互动关系与覆盖回执
→ 课程世界 / Graph / 机会识别 / 研判
→ 影子结果与运营工作台
```

迁移到新的在线学习社区时，课程研判、预算、调度、运行回执和运营界面不需要重写。主要工作集中在连接器及目标环境验收。

## 2. 当前已经具备的通用基础

| 能力 | 当前实现 | 用途 |
| --- | --- | --- |
| 单客户白标 | `NEXT_PUBLIC_PRODUCT_*` 与 `NEXT_PUBLIC_OPERATOR_LABEL` | 切换产品名、短名称、说明和运营方标签 |
| 通用课程清单 v2 | `platform.course-manifest.v2` | 接受非数字课程引用和非 cMOOC HTTPS 地址 |
| 精确课程绑定 | 课程引用摘要、规范地址摘要、允许来源集合 | 防止配置漂移到另一门课或另一套环境 |
| 精确连接器注册 | `[platformId, adapterId]` 双键 registry | 未注册或平台/连接器错配时停止，不回退到 cMOOC |
| 数据库连接器绑定 | Manifest 表持久化 `adapterId` | 已运行课程不能静默换用另一连接器 |
| 运行证据续接 | 去正文语义回执可跨重试恢复 | 重试时不必重新读取或保存课程正文 |
| 有界课程队列 | 稳定 keyset 分页 | 500 门以上启用课程不会因固定窗口而长期饥饿 |
| 旧预演入口收口 | 无显式课程地址即拒绝 | 不再悄悄落到某个历史课程 |

## 3. 目标社区连接器的最小契约

连接器至少提供一个 `observe()` 实现，输出统一的扫描结果：

- 课程扫描覆盖：读取范围、完成范围、失败目标和截断状态；
- 版本化事件：主题、回复、成员互动及必要的课程结构事实；
- 稳定匿名键：同一课程对象在重试和增量扫描中保持一致；
- 去正文回执：持久层只保留哈希、计数、状态和可核验绑定；
- 进度游标：长扫描可安全续跑，不把重复第一页当作完整覆盖。

连接器不能自行发布、签发许可或改变课程策略。编辑器暂存与真实发布属于独立的后续能力。

## 4. 一次目标社区迁移的六个步骤

### 步骤 1：冻结目标环境

由目标方提供测试租户或测试课程，并确认：

- 课程首页或规范地址；
- 课程、栏目、主题、回复、成员的只读数据入口；
- 认证和会话续期方式；
- 分页、删除内容、限流和错误码；
- 是否存在可回读并可清除的编辑器测试面。

### 步骤 2：建立课程清单

在仓库中保存不含真实课程标识的 template，在部署机受控目录保存实际 manifest。两者共同绑定平台、连接器、课程引用、规范地址、允许来源、预算和调度。

```text
仓库：configs/courses/<alias>-course.template.json
部署机：COURSE_MANIFEST_DIR/<alias>-course.json
```

课程凭据、Cookie、token、正文和身份不进入这两份文件。

仓库提供了可复制的 [纯 synthetic v2 示例](../configs/courses/examples/README.md)，其中
template 与 manifest 的课程引用、URL 和两个 SHA-256 已保持一致。

### 步骤 3：实现只读连接器

按 `platformId + adapterId` 注册工厂，将目标平台数据规范化为现有事件和结构事实。首版只做读取、增量游标、覆盖回执和失败分类。

### 步骤 4：通过合成与测试课程验收

先用 synthetic fixture 验证课程绑定、分页、重试、去重、父回复闭合和零平台写入，再在目标测试课程运行 `OBSERVE`。

### 步骤 5：进入影子研判

只在覆盖可靠后启用 `SHADOW`。系统可以形成课程世界、Graph、机会和草稿，但不写编辑器、不提交消息。

### 步骤 6：单独评估暂存能力

只有目标社区提供稳定的编辑器写入、唯一回读和清除机制时，才开发 `STAGE` 适配。真实提交仍需要另外的课程策略、许可和发布验收。

## 5. 交付验收表

| 验收项 | 必须达到 |
| --- | --- |
| 课程绑定 | 错课程、错 URL、错 origin、错 adapter 均在读取前拒绝 |
| 分页完整性 | 能区分完整、截断、服务端重复页和内容删除 |
| 重试 | 同一扫描可续跑；重复事件不重复入账 |
| 隐私 | 普通数据库、日志和 API 响应不含课程正文、身份或凭据 |
| 队列 | 501+ 启用课程仍能发现分页边界后的到期课程 |
| 工作台 | 桌面和移动端可查看课程脉搏、运行、结果和治理 |
| 写入边界 | `OBSERVE/SHADOW` 的编辑器写入与发布尝试均为 0 |
| 生产构建 | migration、测试、类型检查、Lint 与 Next.js build 通过 |

## 6. 小盒联调启动清单

开始小盒连接器前，需要目标方给出以下材料：

1. 测试环境地址与测试课程；
2. API 文档，或允许只读观察的页面结构说明；
3. 认证、会话续期和限流规则；
4. 课程、主题、回复、成员对象的样例响应；
5. 删除、隐藏、审核中内容的表示方式；
6. 若要展示暂存能力，提供专用测试编辑器及清除规则。

有了这些材料，首个小盒版本应按“一条真实只读纵向链”交付，而不是先做一个声称支持多平台、但没有目标环境证据的通用壳。

## 7. 采购演示主线

推荐用同一门测试课程连续展示：

```text
社区接入准备度
→ 课程脉搏
→ 互动网络与支持缺口
→ 一次只读巡检的运行回执
→ 影子研判结果
→ 治理、异常与零发布证据
```

这条主线展示的是可迁移的产品内核、可核验的运行工程和完整运营界面；目标平台联调状态则由“社区接入”页明确展示。
