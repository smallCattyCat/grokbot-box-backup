# P1c 角色来源与动态促进功能分层报告

日期：2026-07-18（Asia/Shanghai）

## 结论

P1c 已把平台身份、内容来源和促进功能拆为独立维度，并对真实的 2024—2025 cMOOC 论坛导出创建了隔离研究数据库。平台 `CREATOR` 现在原样保存为 `creator`，不再自动解释为 `teacher`。所有历史来源仍为 `unknown`，学习者画像投影继续关闭。

核心原则是“身份分层但不分级，来源可追溯，促进功能按事件动态标注”。平台角色只说明课程名册中的登记状态，不产生网络先验权重；任何参与者都可能在某个事件中承担资源引介、观点连接、综合或情感支持功能。

## 新增研究结构

### `actor_role_claim`

保存带证据来源的身份声明。当前只写入课程名册中的平台角色，权威来源为 `platform_roster`。以后只有行政账号清单、学伴部署日志或明确的人工标注，才能增加 `source_provenance` 声明；帖子长度、网名或模型猜测不得成为身份真值。

### `event_function_score`

预留事件级、多标签促进功能，包括资源播种、问题引导、观点连接、放大、综合、认知挑战、情感支持、组织协调和同伴交流。每条标签必须保存概率、标注来源、代码本或模型版本、时间截点和是否使用未来信息。数据库约束禁止未来条件化标签进入在线策略。

### 结构信号与审阅队列

`forum_event_content` 只保存内容 HMAC、净字符数、段落数、URL 数和截断标记，不保存正文。`facilitation_review_queue` 使用课程内 P95/P99 将异常长主帖送入人工审阅，并固定输出 `review_candidate_only_no_identity_inference`。它不是促进者分类器，也不会改变作者的平台角色。

### 分析视图

- `network_ecology_nodes`：纳入全部参与者的社区生态节点，不按角色预赋权重。
- `learner_state_focal_events`：严格学习者状态证据；当前因来源和快照可用时间未确认而为空。
- `interaction_context_events`：可作为历史环境和干预机会的上下文事件；不得混入学生人格真值。
- `event_structure_rank`：课程内结构排名，用于分层抽样和敏感性分析。
